# 飞鹤输入法（feihe）

Windows TSF（Text Services Framework）中文输入法。Rust + windows-rs 实现 COM 组件。

**当前版本 0.3.0** ｜ 安装包 1.61 MB ｜ 装完约 6.5 MB ｜ 单字 8006 ｜ 词条 46492 ｜
不联网、不弹窗、无账号 ｜ 185 项单元测试 ｜ 用户级安装，不需要 UAC

> 数据全部和 DLL 放在**安装目录**里（默认 `%LOCALAPPDATA%\Feihe`）：`config.ini`、
> `freq.txt`、`phrases.txt`、`pinned.txt`。**压缩一份安装目录就是完整备份**，
> 换机、重装直接拷回去。

> 项目主页（GitHub Pages）在 [`index.html`](index.html)，单文件、零依赖，直接当落地页用。
> 启用方式：仓库 `Settings → Pages`，Source 选 `main` 分支根目录即可。

> **读哪里**：只想用 → 「怎么打字」「快捷输入」「标点」「状态浮窗与设置」；想自己编 →
> 「构建」「测试」「打安装包」；想换词库 → 「词库」「数据源与下载缓存」「导入搜狗词库」。
> **设计取舍和踩过的坑在 [`handoff.md`](handoff.md)，发版前的验收步骤在
> [`docs/验证清单.md`](docs/验证清单.md)**——这两份不随安装包分发。

## 和主流输入法比，飞鹤是什么定位

一句话：**一个只有几 MB、不联网、不弹窗、源码全开的双拼输入法**。
不打算取代搜狗的全功能，只服务「只想安安静静打双拼」的人。

体积数据是本机实测（搜狗 16.3.0.3446 装完 134 MB / 81 个文件，用户数据另占 7.8 MB）：

| 维度 | 飞鹤 | 搜狗拼音 | 微软拼音 |
|---|---|---|---|
| 安装包 | **1.39 MB** | 百 MB 量级 | 随系统预装 |
| 装完占用 | **约 6.0 MB**（两份 DLL） | 134 MB + 用户数据 | 随系统 |
| 广告 / 热点推送 | **没有这功能** | 有（可在设置里关） | 无 |
| 账号 / 联网 | **完全不需要** | 登录后云同步 | 微软账户可选 |
| 开源 | **是**（Rust，全文可改） | 否 | 否 |
| 小鹤双拼 | **原生**，不用装方案 | 支持 | 支持 |
| 一简 / 二简 | **原生**（一简 26 键含次选，二简 370 词） | 随方案 | 无 |
| 词库规模 | 4.7 万条 | 数百万级云词库 | 系统词库 |
| 生僻字 | GB2312 + 通用规范汉字表**全收，缺 0** | 全 | 全 |
| 动态词频 | 本地学习 | 云端 + 本地 | 本地 |
| 简繁切换 | Windows NLS，零体积 | 有 | 有 |
| 皮肤 | 3 套内置 | 皮肤商店 | 少量 |
| 模糊音 | **无** | 有 | 有 |
| 语音输入 | **无**（M5 已搁置） | 有 | 有 |
| 云同步 / 云词库 | **无** | 有 | 有 |
| 候选窗点击选词 | **有** | 有 | 有 |

**它真正占优的地方，都是「少」带来的：**

- **体积差两个数量级**。词库在构建期预编码成扁平二进制，`include_bytes!` 嵌进 DLL 的
  `.rdata`；PE 加载器 mmap 它，**多个进程共享同一份物理页**。没有运行时解析、没有
  每进程私有堆，所以 4.7 万条词库只值 2.9 MB。
- **没有联网代码**。整个 DLL 的导入表里没有任何网络 API，这不是「隐私承诺」，是
  「没写这个功能」。实测 18 个导入 DLL 全是 `kernel32` / `user32` / `ole32` / CRT 这一层，
  没有 `wininet` / `winhttp` / `ws2_32` / `urlmon`。自己验：

  ```cmd
  objdump -p feihe.dll | findstr /i "DLL Name"
  objdump -p feihe.dll | findstr /i "internet winhttp ws2_32 urlmon"
  ```
- **改一行就能重新编译**。不喜欢候选顺序、想加个快捷输入命令、想换皮肤颜色，
  改 Rust 源码 30 秒出包，不用等官方发版。
- **双拼是一等公民**。不是「全拼输入法附带一个双拼模式」，键位表本身就是规格，
  单元测试拿官方反查结果钉死（`按钮` = `annq` 这种零声母细节）。
- **不自动上屏**。长句一定是「你按空格才落字」，不会替你猜一半先写进文档。
- **简码是一等公民**。一简 26 键（每键还有次选，分号直接取）、二简 370 条两键词，
  词表就是 `src/brief2.txt` 这样一个纯文本文件，删一行就少一个，不用等发版。

**它明确不如人的地方，也说清楚：**

- **词库差得远**。4.7 万条是「够日常」的量级，不是「什么都有」。专业术语、
  网络新词、人名地名基本查不到，得靠用户词库补（支持导入搜狗个人词库，
  见后文）。
- **没有云**。换电脑不同步，词频学习只在本机。
- **模糊音、语音、手写都还没有**（语音原计划 M5，已搁置）。
- **安装包未签名**，首次运行会撞 SmartScreen。

如果你要的是「功能最全的中文输入法」，用搜狗或微软拼音；如果你要的是
「一个安静、干净、能改的双拼引擎」，飞鹤就是为这个做的。

## 怎么打字（小鹤双拼）

**不是全拼。** 每个音节固定两键：声母键 + 韵母键。

```text
声母键位
zh=v   ch=i   sh=u
其余声母直接用字母本身（b p m f d t n l g k h j q x r z c s y w）

韵母键位（口诀：秋闱软月云梳翅，松拥黛粉更航安，快莺两望奏夏蛙，撇草追鱼滨鸟眠）
q=iu   w=ei   e=e    r=uan   t=ue   y=un   u=u   i=i   o=o/uo  p=ie
a=a    s=ong  d=ai   f=en    g=eng  h=ang  j=an  k=uai  l=iang
z=ou   x=ia   c=ao   v=ui    b=in   n=iao  m=ian
```

规则：
- `zh` / `ch` / `sh` 落在 `v` / `i` / `u`（`zhong`→`vs`、`chi`→`ii`、`shi`→`ui`）。
  注意这三个键与韵母键复用，位置不同不冲突
- 零声母**按韵母长度分三种**（这是最容易记错的一条，官方「小鹤入门」1.1）：

  | 韵母长度 | 规则 | 例 |
  |---|---|---|
  | 1（`a` `o` `e`） | 重复该字母 | 啊 `aa`、哦 `oo`、额 `ee` |
  | 2（`ai` `ei` `ao` `ou` `an` `en` `er`） | 零声母 + 韵母**末**字母，**表现同全拼** | 爱 `ai`、安 `an`、恩 `en`、欧 `ou` |
  | 3（`ang` `eng`） | 零声母 + 韵母所在键 | 昂 `ah`、鞥 `eg` |

  所以「按钮」是 `annq`（`an` + `nq`），不是 `ajnq`。
- `ü` 写作 `v`（`lv`→`lv`、`xue`→`xt`）

例子：

| 想打 | 全拼 | 实际敲 |
|---|---|---|
| 你好 | ni hao | `nihc` |
| 中国 | zhong guo | `vsgo` |
| 我们 | wo men | `womf` |
| 世界 | shi jie | `uijp` |
| 是 | shi | `ui` |
| 水 | shui | `uv` |
| 的 | de | `de` |
| 按钮 | an niu | `annq` |
| 安全 | an quan | `anqr` |
| 爱情 | ai qing | `aiqk` |
| 欧洲 | ou zhou | `ouvz` |
| 肮脏 | ang zang | `ahzh` |

操作：**空格**选第一个候选，**回车**把已敲的编码原样上屏（`iuliqi` → `iuliqi`，
不选候选），数字键 `1-9` 选对应候选，`←/→` **切到逐字选择**（多音节码，见「长句」；
单音节码里是页内移动），`-` `=` 或 `↑` `↓` 翻页
（`-`/`=` 是搜狗、微软拼音的通行键位；组合态下这两个键归翻页，想打 `－` `＝` 先上屏）。
退格删一个键（分词模式下一次退一个音节，见下节），`Esc` 取消。`Ctrl` / `Alt` / `Win` 组合键一律放行不拦截
（两个例外：`Ctrl+数字` 置顶、`Ctrl+Shift+U` 临时切换弹窗，见下）。

### 一级简码

26 个键各配一个「这个键底下最常用的字」，敲一个键它就是第一候选，空格直接上屏：

```text
q 去   w 我   e 二   r 人   t 他   y 一   u 是   i 出   o 哦   p 平
a 啊   s 三   d 的   f 发   g 个   h 和   j 就   k 可   l 了
z 在   x 小   c 才   v 这   b 不   n 你   m 没
```

口诀：去我二人他，一是出哦平；啊三的发个，和就可了；在小才这，不你没。

`u`=是、`v`=这、`i`=出 看着奇怪，其实是一致的：小鹤双拼里 `u`/`i`/`v` 兼 `sh`/`ch`/`zh`，
所以「是/出/这」的码分别以 `u`/`i`/`v` 开头。

只对**单键**生效，敲第二个键就回到正常排序。一简字排在动态调频前面——这是打字的
肌肉记忆，不该被偶发学习顶掉；想换就用下面的置顶。

**每个键还有次选**，固定占第二位，分号键直接取（跟小鹤的习惯一致）：

```text
q 期    w 位    e 嗯嗯   r 然后   t 提供   y 有时   u 时    i 重新   o 哦哦   p 便宜
a 安装  s 所有  d 打     f 复杂   g 管     h 忽略   j 见    k 可以   l 理解
z 自动  x 显示  c 词库   v 之     b 比较   n 内容   m 没有
```

`d;` 出「打」、`c;` 出「词库」；不按分号时它就待在第二位，数字 `2` 一样能选。
注意这会挤掉原来的第二位（`d` 的第 2 位从「大」变成「打」）——这是小鹤的既定排法；
实在不想要，用 `Ctrl`+数字 把你要的字置顶，或者把 `brief.rs` 里 `ALT` 表清空。
分号在**别的位置**仍然是手动分隔符（`nihao;ma`），只有「刚敲了一个字母」这一种情况
才当次选键——单键后面本来也插不进分隔符（双拼要求断在完整音节之后）。

### 二级简码（二简词）

两键出一个常用两字词：两个字各取自己**双拼码的第一个键**。`难`(nan)→`n`、`道`(dao)→`d`，
所以 `nd` 出「难道」；`拼`(pin)→`p`、`音`(yin)→`y`，`py` 出「拼音」。

```text
nd 难道   py 拼音   jd 简单   sy 所以   wm 我们   xz 现在
jj 解决   bt 不同   um 什么   vd 知道   ux 首先   zx 在线
```

词表 370 条（小鹤官方「二简词」首选 273 + 次选 97），在 `src/brief2.txt`，可自己改。

**首选 / 次选**：两键码是稀缺资源，好码早被单字占了（`mm` 是「面」、`uu` 是「书」）。
所以这类码上的词算**次选**，排在那个字**后面**：打 `mm` 第一位仍是「面」，「慢慢」第二位；
打 `nd` 第一位是「难道」，「奶」退到第二位（数字键照样能选）。

**和单字撞码是故意的**：370 条里 103 条的两键码本身就是合法音节（`nd` 本是「奶」、
`sy` 本是「孙」、`lj` 本是「蓝」）。小鹤就是这么排的——要那个字就按数字选，或者用下面
的置顶把它钉回去。真嫌碍事，把 `src/brief2.txt` 里那一行删掉即可。

只在小鹤方案下生效（微软双拼的两键码含义不同，套上去会张冠李戴）。

### 手动置顶

两种做法，效果一样：

- **`Ctrl` + `数字`**：把这个候选钉到当前编码上并**上屏**，以后这个码永远先出它。
  对已经置顶的那个词再按一次就是取消。
- **右键点候选**：同样切换置顶，但**不上屏**、不打断组合态。这一条是给多页签程序
  准备的——浏览器、VS Code、JetBrains 都把 `Ctrl+1..9` 抢去做「切到第 N 个页签」，
  那些窗口里根本收不到这个组合键。右键切换后候选立刻重排（钉的词跳第一位），
  这就是反馈，不弹任何提示。

> 全屏游戏走 UILess 时候选由宿主绘制、没有我们的候选窗，右键用不了；那种场景用置顶
> 只能在桌面窗口里先钉好。

优先级：**手动置顶 > 一简首选 > 一简次选（占第 2 位）> 二简首选 > 自造词 > 动态词频 > 静态词频**。置顶记录在
`<安装目录>\pinned.txt`（`编码<TAB>词`），可手改、可整删；设置窗能看能清空。

> 置顶**不受 `limit` 截断限制**：词排到第 90 名以外也能被钉上来，这是它和
> 动态词频最本质的区别（后者只能重排「已经在候选列表里」的词）。

### 自造词（拼出来的新词会记住）

词库里没有的词（人名、公司名）靠「分词 + 退格拆词」能打出来，但**拼一次只顶一次**：
下次敲同样的码又得从头拆一遍。所以分词上屏时会把整串记下来：

```text
第一次：limkyr → 退格拆词 → 选「李」「明」「远」 → 上屏「李明远」
之后：  limkyr → 候选第一位就是「李明远」
```

记的是**全拼**而不是双拼码（`li ming yuan`），所以换方案、切全拼模式都还能打。
全拼从词库里逐段反查（`dict::pinyin_of` 走整码匹配，不做前缀——只按前缀扫会把
`limk`（李明）的全拼错配给单字「李」）。

准入规则在 `textservice::compose_phrase`（纯函数，单测覆盖）：至少两段、每段都真有词、
段码拼起来等于用户敲的那串、词库里本来没有。任何一条不满足就不记——自动分词沿用默认
候选时不该往表里灌重复数据。

记录在 `<安装目录>\phrases.txt`（`词<TAB>全拼<TAB>次数`，第三列可省）。**同码多个词按次数排**，次数相同才比新旧——早期只有「新学的在前」，等于最后造的永远压着常用的那个，删掉即全忘；
设置窗的「动态调频」一栏显示条数并支持一键清空。关掉动态调频就不再记新词。

**同一个码可以挂多个词。** 学会「李明远」（`limkyr`）之后，再想用同一个码造「李明源」
（同音不同字的人名）：敲 `limkyr`，按一下 **`←`**（或 `→`）——编码会切成
`[李][明][远]` 三段，用数字键把最后一个字换成「源」，空格确认到底。新词进候选第一位，
「李明远」退到第二位，两个都留着。按 `←`/`→` 进分词模式**不受「整串已有候选」限制**，
这是同码再造一个词唯一的路——退格在这里只会删字母。


**鼠标也能选词**：直接点候选窗里的那一项就上屏。窗口不抢输入框焦点，点完继续打字
仍然进组合态；按下后拖到窗外再松开算取消，不会误上屏。候选数量按码长衰减——
单键 18 个（2 页）、两键 45 个，三键以上才满 90。

**单击 Shift** 切中英文（按住期间按过别的键就不算单击）。**`Shift + 字母` 直接上屏大写**：
中文态下 Shift 不进编码，按住它敲 `A` 得到的就是 `A`，不会像以前那样和直接敲 `a` 没区别；
已有组合串会先按当前候选结掉，再粘上这个大写字母（`ni` + `Shift+A` → `你好A`）。
切到英文后所有按键原样进应用，候选窗不弹。

**不会自动上屏。** 只有显式动作（空格 / 数字 / 回车 / 标点）才会把字写进文档。
音节敲完但整串查不到候选时，输入法不会替你挑一个先放着——它切成多段挂起来，
让你一段一段选（见下节）。想把汉字写进文档就按空格逐段确认（最后一段自动整体上屏）；
回车永远是「我就要这些字母」。

> 早期版本做过「边打边上屏」：整串没候选时把左边能匹配的部分直接上屏、剩下的开新一轮。
> 实际用起来是灾难——打 `viuiq` 想输入「指示器」，屏幕上凭空出现「只是」，
> 后面的 `qi` 又变成一个新的单字组合。已删除。

### 易错词的读音提示（按错读音也能打出来）

多音字词的读音，词库每条只存一个。`重庆` 挂在 `chong qing` 下，按 `zhong qing` 打
永远出不来——用户并不知道自己读错了，只会以为词库里没收这个词。所以候选窗做了两件事：

```text
1.重庆 chóng qìng   2.弹窗 tán chuāng   3.你好   4.银行 yín háng
        └── 小一号灰字，只在易错词后面出现
```

- **标注读音**：易错词后面跟一串带调的拼音，就在候选里，不用去查；
- **错音容错**：按**默认读音**打也能出，追加在该码正常候选的**末尾**。打 `zhongqing`
  先出「钟情」（它本来就是这个词），翻到最后还有「重庆」。

「易错」的判定是逐字比较：词库读音 ≠ 这个字的默认读音、且该字是多音字。全库 4.6 万条
里只有 **753 条**（`重庆`、`弹窗`、`川芎`、`六安`、`水雷屯`…），表在 `src/hint.txt`，
26 KB，随 DLL 发布。其余词的读音没有歧义，不标注也不占宽度。

设置里可以关掉标注（`reading=0`），候选窗宽度回到旧样子；错音容错不受这个开关影响
——它多给一个候选，不多占一个像素。

代价是 26 KB 的表：安装包 1.56 → 1.58 MB、64 位 DLL 3667 → 3706 KB。换来的是 753 个
易错词既能标对读音、又能按错读音打出来；不引任何依赖（pypinyin 只在生成期跑）。

### 长句：智能分隔 + 分词选择

打得多、整串又查不到词的时候（`nihaoshijie` 这种），飞鹤会先把编码切成音节，
再按「每段都能出候选」切成若干段，进入**分词模式**：

```text
组合串显示：[你好]世界      ← [] 里是当前段
←/→   移到上一段 / 下一段
1-9   给当前段换词（候选窗显示的是这一段的候选）
空格  确认当前段并跳到下一段（最后一段则整体上屏）
回车  原样上屏字母（已确认过的段保留汉字）
退格  拆开当前段（词 → 单字）；全是单字了才退掉最后一个音节
继续敲编码键 → 延长组合串并重新分段，已选过的段会保留
```

**回车 = 字母，不是候选。** 分词模式曾经把回车做成「整体上屏」，于是任何能切成音节的
英文串都会被翻译成汉字——打 `mmap` 出「面ap」（`mm`→面，`ap` 没有候选只能当字母），
用户没法预判回车到底出什么。现在两个模式的回车是同一个语义：上屏你敲的字母；
只有**手动确认过**的段保留汉字（那几段是你明确选的，不能连人带字一起丢掉）。
想在分词模式里整句上屏，按空格确认到底即可。

**退格拆词。** 自动分段的依据是「词库里能匹配上的最长段」，所以 `limkyr` 会切成
`[李明]远`。如果你要的是「李」+「明」+「远」，按一次退格把 `李明` 拆成两个字——
候选窗立刻变成「李」的字候选，选完自动跳到「明」。**这一步不丢编码**，再按一次退格
才真的删掉末尾音节（`limkyr` → `limk`）。

光标停在单字上时，拆的是最后一个还能拆的段：退格的方向是从右往左，你想改的通常是
刚打出来的那个词。全拆成单字之后，再退就是退音节，回到「整串有候选」的普通编码态。

**整串有候选也能进。** 自动分词只在「整串一个候选都没有」时触发，但 `←`/`→` 是**手动**
入口，任何多音节码一按就切——包括已经有候选的情况（自造词就长这样：`djdjth` 整串是
「蛋蛋堂」一个词）。切进去之后每段都退到单字粒度，改完按空格逐段确认到底即可。
单音节的码（`de`、`ni`）切不出第二段，`←`/`→` 在那里还是页内移动。

要一开始就不让它乱组词，也可以直接敲分隔符 `'` 指定边界（见下节）。

**继续敲字母不会上屏**，只会把编码接长、重新分段。所以长句可以一口气打完再逐段挑。

全拼和双拼都支持。全拼的音节边界不定长（`ni` 两字符、`hao` 三字符、`zhuang` 六字符），
用 DP + 音节合法性校验来切，长音节优先（`xian` 不会切成 `xi`+`an`）。

### 手动分隔

自动切分不理想时，可以用 `;` 强制断一刀：

| 模式 | 分隔键 | 原因 |
| --- | --- | --- |
| 全拼 / 小鹤双拼 | `;` | 这两种编码里没有分号 |
| 微软双拼 | `'` | 分号被 `ing` 韵母占用（`;` = ing），只能换成单引号 |

例子：`xi'an` 强制切成 `xi`+`an` 而不是 `xian`；`ni'hao` 断在 `ni` 后面。
分隔符只是打字辅助，**不会进文档**（回车原样上屏时会去掉）。
位置不合理的分隔符（开头、连续两个、双拼切在半截音节上）会被直接吞掉，不打扰输入。

`Tab` 进入**辅助码**筛选（组合串会显示成 `de b` 这种形式），再按 `Tab` 退出。
辅助码方案在设置里选：自然码辅助码（1 键，取部首声母，如 的→白→`b`）或
小鹤音形（2 键，取首末部件，如 带→带上+巾→`fj`、打→扌+丁→`fd`）。关掉时 `Tab`
原样还给应用。

**先连打、再按 `Tab` 也认**：把形状码一起敲完（`ddj`、`ddfj`）再按 `Tab`，末尾能当
辅助码用的键会自动挪过去，组合串直接变成 `dd j` / `dd fj`，不用退格重来。

**为什么必须按 `Tab`**：`ddj` 本身是个合法前缀——`代价`、`待机`、`贷记`、`带进` 的
码都以 `ddj` 开头，`dd + j` 既可以读成「带 + 价没打完」，也可以读成「带 + 部首 j」。
键盘不可能知道你心里想的是哪个，所以辅助码需要一个明确的进入信号（搜狗双拼同一个
设计）。两条路都留着：`dd` → `Tab` → `j`，或者 `ddj` → `Tab`。

**3 键直出单字（设置里可选，默认关）**：打开之后 `ddj` 不用按 `Tab`，第 3 键直接
当形码，第一位就是「带」。代价很实在——`代价`、`待机` 这类词也因此打不出来（退格
一次会记住「这次别拆」，能正常打）。双拼每个音节固定 2 键，所以只有「1 个完整音节
+ 1 个孤立键」这唯一一种情况会有歧义，开关只管这 3 键；`ddfj` 这种 4 键码不归它管。

小鹤那一列用的是**官方码**（`react.xhup.club` 反查出来是什么就是什么），不是自己
推算的。早先按 IDS 部件分解推过一版，和官方只有 12% 一致——官方有「带上 / 寿上 /
具上 / 既左」这类专用字根，还有「孰大优先 / 相交不拆 / 插隔不取」这些得看笔顺才
判得了的规则，推不出来。码错了不会报错，只会让你筛出一片空白，所以宁可先抓下来
入库（`tools/xhup_cache.txt`，随仓库走）也不猜。

打法示例（小鹤音形）：`dd` → `Tab` → `f` → `j`，第一位就是「带」。

码表覆盖词库里全部 8007 个字（小鹤 7866 个，其余 141 个是「亻 / 冖 / 卍 / 艹」这类
只作部件或极冷僻的字，官方库本身没有码）。表 72 KB，压进 DLL 之后 64 位主程序
3706 → 3746 KB，安装包没变（1.58 → 1.59 MB，只涨了一点）。

## 快捷输入（日期 / 时间 / 农历 / 干支 / 节气）

先敲 `/`（斜杠，`?` 那个键），后面接命令码。**只打首字母也行**——八个命令的
首字母互不相同，`/r` 就等于 `/rq`。

| 输入 | 得到 |
|---|---|
| `/rq` | `2026年10月22日` / `2026-10-22` / `2026/10/22` / `2026.10.22` / `10月22日` / `22日` |
| `/sj` | `17:40` / `17:40:06` / `下午5点40分` / `下午5:40` |
| `/xq` | `星期四` / `周四` |
| `/dt` | `2026-10-22 17:40:07` / `2026-10-22 17:40` / `2026年10月22日 17:40` / `… 星期四` |
| `/ts` | Unix 秒 / Unix 毫秒 |
| `/nl` | 农历：`农历丙午年九月十四` / `丙午年九月十四` / `九月十四` |
| `/gz` | 干支四柱：`丙午年 戊戌月 庚午日 壬午时` / `丙午 戊戌 庚午 壬午` / 三柱（不带时） |
| `/jq` | 下一个节气：`2026年11月7日 立冬` / `11月7日 立冬` / `立冬` |

只敲一个 `/` 会列出全部命令的**当前值预览**（按空格拿日期，按数字选别的），不用记码。

**农历 / 干支 / 节气统一用 [Tyme](https://6tail.cn/tyme.html)**（`tyme4rs`，MIT）：
节气算法引自寿星天文历，农历、干支、节气共用同一套儒略日，三者不会互相打架。
自己写这套等于重造万年历，边界（闰月、立春换年、子时换日）几乎必错。

两个容易误解的点：

- `/nl` 的干支年**按春节换年**（农历年），`/gz` 的年柱**按立春换**（四柱年）。
  春节和立春之间那几天，两者给的年不一样——这是对的，本来就是两套历法。
- `/jq` 给的是「最近的下一个」节气，精确到日；今天正好是节气当天就给今天。

> **为什么不像搜狗那样直接打 `rq`？** 搜狗是全拼，`rq`、`sj` 不会撞车。飞鹤是双拼，
> 两字母恰好就是一个音节：`sj` = `s`+`an` = `san`（三），`xq` = `x`+`iu` = `xiu`（休）。
> 照搬的话一半命令会被词库吃掉，行为不可预测。所以统一加引导符。
>
> **引导符为什么是 `/`？** 顿号只留 `\` 一个键（搜狗习惯）就够了，`/` 位置好记好按，
> 拿来当功能入口更划算。中间一度搬到反引号（理由是「`/` 和 `\` 都要出顿号」），
> 但反引号太偏、记不住，最后还是换回 `/`。代价是中文态下 `/` 不再出 `、`——
> 想打半角斜杠，敲 `/` 再回车（只敲了引导符本身时，回车原样上屏 `/` 或 `／`）。

## 标点

开「全角标点」（新装默认开）后，中文态下这些键直接出中文标点：

| 键 | 得到 |
|---|---|
| `,` `.` | `，` `。` |
| `\` | `、`（顿号只留这一个键，搜狗习惯） |
| `;` | `；` |
| `[` `]` | `【` `】` |
| `'` | `’` |
| `-` `=` | `－` `＝` |
| `/` | 不是标点，是快捷输入引导符 |

Shift 组合里**只有字母由飞鹤处理**（直接上屏大写，见上面「怎么打字」末尾那两段）。其余一律交给应用自己算：
`Shift+\` 出 `|`、`Shift+/` 出 `?`、`Shift+,` 出 `<`——这些字符由键盘布局决定，
按 VK 自己映射会在非 QWERTY 布局上算错，所以不去碰。

组合串还没上屏时按标点键也走同一套规则：先把候选上屏、紧跟着粘上全角标点，
**不会**出现「，,」两个字符。

## 状态浮窗与设置

屏幕右下角（可拖动，位置会记住）有一条小横条，四个按钮：

| 按钮 | 作用 |
|---|---|
| 中 / 英 | 切换中英文（等价于单击 Shift）。开了繁体时这里显示「繁」 |
| 全 / 半 | 全角标点开关（`,。\、；【】’－＝` 这一排） |
| 符号 | 弹出 9×5 特殊符号面板，点一下插到光标处 |
| 设置 | 打开设置窗 |

> 皮肤和「全拼 / 双拼」原来也在这条浮窗上，后来挪进设置窗了——它们改一次就长期不变，
> 占着浮窗宽度不划算。浮窗只留随时要按的开关。

设置窗：输入模式（双拼 / 全拼）、双拼方案（小鹤 / 微软）、辅助码方案（关闭 / 自然码 /
小鹤音形）、皮肤（浅色 / 深色 / 护眼）、字形（简体 / 繁体）、全角标点、
浮窗是否跟随光标、**候选窗何时收起（自动 / 始终弹出 / 始终不弹）**、动态调频 + 自造词（含「重置」）、**置顶（含「清空」）**、
词库统计 + 导入 / 导出 / 编译。

全拼模式是给访客的应急通道：切到全拼就能直接敲 `nihao` 出「你好」，不用学双拼。
词库走另一套「全拼去空格」索引，第一次切过去时建索引约 60ms，之后复用。
早期它不写盘（怕借电脑的人忘了切回来），现在放进设置窗就必须持久化——
设置项改了重启就失效太费解。

**繁体**是逐字映射（`设置` → `設置`），走 Windows 自带的 NLS 表
（`LCMapStringEx` + `LCMAP_TRADITIONAL_CHINESE`），不带外部字表、不增加安装包体积。
候选窗、组合串、上屏文本三处一起转，看到什么就打出什么。转换失败时原样输出简体，
绝不吞字。

**动态词频**：你实际选了哪个词，下次它就往前排。静态词频来自 rime-ice 的通用语料，
解决不了「我的高频词」——医生打「诊断」、程序员打「函数」，在通用语料里都排不到前面。
学习记录存在 `<安装目录>\freq.txt`（纯文本 `码<TAB>词<TAB>次数`，删掉即重置，
设置窗里也有「重置」按钮）。只学「从候选里选中的词」，回车原样上屏、快捷输入、
软键盘符号都不学。排序是**稳定排序**，键是 `(码长, 学习次数)`：

- **码长先行**：`ig` 是「成」的整码（2 键），「程序」只是前缀匹配（4 键）。学过几次
  「程序」之后，敲 `ig` 按空格出来的必须还是「成」。码长短 = 更完整，这条不能被学习结果
  覆盖（早期版本只按次数排，`ig` 第一位真的会变成「程序」）。
- **同码长内才比次数**：学过的往前挪，次数相同保持词库原序；没学过的词相对顺序完全不动。
- **次数按「码 + 词」记，不按词记**：多音字一个词挂好几条读音（`哦` 既有 `oo` 也有 `ee`、
  `重庆` 既有 chong 也有 zhong）。只按词记的话，你在 `oo` 里选过 8 次「哦」，`ee` 下它
  也会被顶到第一位，把「饿 / 呃 / 额」全压下去——看到的就是「怎么冒出来个 哦」。老版本
  的 `词<TAB>次数` 记录仍然认（对全部码生效），一旦某个词有了按码的记录，老记录自动退休。

记事本 / Word / 浏览器各加载一份 DLL，各有内存表，所以写盘前会先合并磁盘内容
（同词取较大值，不相加），切输入法时再按 mtime 拉取别的进程学到的词。多进程这块
为什么这么设计、以及删除操作为什么不能走合并，见 `handoff.md`「动态词频」。

**上限与淘汰**：最多 5 万条记录、单条最多 1000 次。满了不是「拒收新词」（早期版本就是
这么写的，表现是「用半年突然不灵了」——表里全是一次的旧记录，新词永远学不进来），
而是按 `(次数, 最久没动)` 淘汰最弱的 1/8。单条次数到顶时**全表减半**（`(n+1)/2`，
1 次不会减成 0），相对顺序一根不动——比把次数钉死在 1000 强，否则几个高频词都顶到
上限之后，排序就塌成平局，学习等于失效。

配置存在 `<安装目录>\config.ini`，改完立即生效（同一进程内即时，其它已打开
的应用要重新切一下输入法）。文件里带 `config_ver`；老配置（v1 把全角标点默认成关）
会一次性迁移成全角标点开——之后再手动关掉不会被改回去。

### 全屏游戏：TSF UILess（候选交给宿主自己画）

独占全屏的游戏绕开了 DWM，输入法自己开的窗口**画了也不上屏**。TSF 为此留了一条 UILess
通道：宿主以 `ActivateEx(TF_TMAE_UIELEMENTENABLEDONLY)` 激活线程管理器，我们显示候选前
必须 `ITfUIElementMgr::BeginUIElement` 请示；宿主回 `FALSE`（=「你别画，我来」）就拿走
`ITfCandidateListUIElement`，用游戏的字体画在自己的界面上。

**这是「全屏游戏里能打中文」的真正机制**——不是输入法有黑科技，是游戏在画候选框。
LOL / 原神 / 魔兽世界 / CS2 这些主流引擎都做了宿主侧。宿主不接（回 `TRUE`）或拿不到
`ITfUIElementMgr` 时，本轮激活自动降级回自绘候选窗——宁可候选窗看不见，也不能让按键
流程因为少个接口就断掉。

实现在 `src/uielement.rs`，实现侧的两个坑见 `handoff.md`「TSF UILess」。

### 候选窗什么时候收起（全屏自动检测）

不是「要玩游戏先去改个设置」——2026-10 之后默认就是**自动**：打字的瞬间问一下 shell
「现在是不是全屏」，是就把候选写进组合串、一个自绘窗口都不弹。判据是
`SHQueryUserNotificationState` 的三种状态：

| 状态 | 场景 | 处理 |
|---|---|---|
| `QUNS_RUNNING_D3D_FULL_SCREEN` | 独占全屏的 D3D 程序，典型就是游戏 | 收起 |
| `QUNS_PRESENTATION_MODE` | 投影 / 演示模式 | 收起（别人的屏幕上不该冒出候选窗） |
| `QUNS_APP` | 全屏 UWP（商店版游戏、视频 App） | 收起 |
| 其余（含 `QUNS_BUSY`） | 正常桌面 | 照常弹 |

收起时候选改塞进组合串，组合串是**宿主画在文档里的**，全屏程序里通常还能看见：

```text
nihc  1.你好 2.拟好 3.你号 …
```

设置里仍然是三选一：**自动**（默认）/ **始终弹出** / **始终不弹**。保留手动档不是偷懒，
是因为自动检测有两头都会错：

- 远程桌面、虚拟机控制台里未必报得出「全屏」，但自绘窗口确实显示不出来 → 用手动「始终不弹」
- 无边框窗口跑游戏时 shell 不认为是全屏，候选窗会盖在游戏上 → 用手动「始终弹出」

`Ctrl+Shift+U` 是临时出口：按一次强制切到相反状态，再按一次回到「跟随设置」。**不落盘**，
只管当前这个窗口——它是应急键，不是配置项。浮窗被藏起来时，这也是唯一能回到设置窗的入口
（没有浮窗就没有「设置」按钮），所以这个键必须在「修饰键一律交还应用」那条之前拦。

拦截点放在 `candidate::show` 和 `statusbar::show`——它们是所有显示路径的唯一出口，
拦在上层的话将来加个调用点就会漏。判断结果缓存 400ms（`src/fullscreen.rs`）：
打字是最高频动作，没必要每个按键都跨进程问一次 shell。

> 这个开关原来叫 `uileless`、后来叫 `no_popup`（都是 bool）。真 UILess 落地后两件事同名
> 必然被搞混，所以 `config_ver` 4→5 改名成 `no_popup`、5→6 换成三态的 `popup`。
> `parse` 仍然认旧键：旧值 `1` 保留成「始终不弹」，旧值 `0`（默认值）升级成「自动」——
> 不能把用户明确勾过的行为在升级时悄悄改掉，也不能让老用户永远享受不到自动检测。

两个必须处理的问题：

1. **看不见候选就等于盲打。** 双拼同码字多（`de` 有几十个），只给「空格出第一候选」
   是不够的，所以候选要拼进组合串。
2. **浮窗是进设置窗的唯一入口。** 藏了浮窗就必须有键盘出口，见上面的 `Ctrl+Shift+U`。

做不到的部分：程序如果既不走 UILess、也不显示组合串（极少数完全自绘输入框的引擎），
飞鹤在里面一个字也打不出来。那需要外挂式键盘钩子 + `SendInput`，还要往游戏进程里注入
才能画候选——反作弊会直接判成外挂，不在本项目范围内。


## 构建（Windows 机）

本机环境走 **llvm-mingw** 路线，**无需 MSVC**（VS 未装 C++ 工具集）。
默认**同时产出 64 位和 32 位两份 DLL**。

前置依赖：
- Rust（rustup）
- [llvm-mingw](https://github.com/mstorsjo/llvm-mingw/releases) 解压到 `C:\llvm-mingw`（需含顶层 `bin\`，即 `x86_64-w64-mingw32-gcc.exe`；`i686-w64-mingw32-*` 同一份压缩包里就有）
- `rustup target add x86_64-pc-windows-gnullvm`
- 32 位额外需要：`rustup target add i686-pc-windows-gnullvm`
  （国内直连不通时用镜像：`$env:RUSTUP_DIST_SERVER='https://mirrors.ustc.edu.cn/rust-static'`
  ——清华/阿里镜像不保留历史日期目录，会 404）

一键构建（推荐）：

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1            # 64 + 32 位
powershell -ExecutionPolicy Bypass -File build.ps1 -Arch x64  # 只编 64 位
powershell -ExecutionPolicy Bypass -File build.ps1 -Arch x86  # 只编 32 位
# 产物：
#   target\x86_64-pc-windows-gnullvm\release\feihe.dll   (Machine=0x8664, 64 位)
#   target\i686-pc-windows-gnullvm\release\feihe.dll     (Machine=0x014c, 32 位)
```

`build.ps1` 会自动：定位 llvm-mingw → 为每个架构生成 `-lgcc`/`-lgcc_eh` 兼容库
（compiler-rt + libunwind）→ 禁用 `libunwind.dll.a`（强制静态链接，否则 ctfmon 找不到该 DLL
导致输入法加载失败）→ 设置 PATH → `cargo build` → **校验 PE 头机器类型** →
用对应位数的测试程序跑一遍 `LoadLibrary` + `DllGetClassObject` + `CreateInstance`。

> 背景：Rust 的 `*-gnu` target 硬编码链接 `-lgcc`/`-lgcc_eh`，而 llvm-mingw 用 compiler-rt/libunwind，故需 shim 库。
> `rust-toolchain.toml` / `.cargo/config.toml` 已固定 toolchain 与 target，无需手动指定。

运行时依赖只有一个第三方 crate：[`tyme4rs`](https://github.com/6tail/tyme4rs)（农历 / 干支 / 节气，
MIT）。其余全部是 `windows` / `windows-core` 和标准库——没有 `chrono`、没有 `serde`、没有网络栈。
`tyme4rs` 自己依赖 `regex`（解析中文名称用），那是 DLL 里唯一一块「不必要但甩不掉」的体积。

### 为什么要两份 DLL

in-proc COM 的位数**必须**和宿主进程一致，64 位 DLL 塞不进 32 位进程（反之亦然）。
所以同一个 CLSID 背后挂了两个文件：

| 宿主 | 加载 | 注册表位置 |
| --- | --- | --- |
| 资源管理器 / TextInputHost / 64 位 Office | `feihe.dll` | `HKLM\SOFTWARE\Classes\CLSID\{...}` |
| 32 位 Office、IE 插件、老的 32 位应用 | `feihe32.dll` | `HKLM\SOFTWARE\Classes\Wow6432Node\CLSID\{...}` |

目录本身取决于安装方式：`register.cmd` 用 `%ProgramData%\Feihe\`，
NSIS 安装包用 `%ProgramFiles%\Feihe\`（并会在安装时尽力清掉老的 ProgramData 副本）。

`installer\register.cmd` 两份都会部署并分别注册；`unregister.cmd` 两处都清。
如果只编了 64 位，安装脚本会给出警告并只注册 64 位那份。

### 32 位构建

`i686-pc-windows-gnullvm` 是官方 target，和 64 位同一条路线，`build.ps1` 里就是多跑一次
`cargo build --target i686-pc-windows-gnullvm`，没有额外垫片。

> 别用 `i686-pc-windows-gnu`。它也能编出来，但会多带 `rsbegin.o`，引用 GCC 老式的
> `___register_frame_info` / `___deregister_frame_info`；llvm-mingw 用 libunwind + SEH，
> 没有这两个符号，链接直接失败，得自己写空实现垫上。既然有 gnullvm，没必要绕这一圈。
> （本项目早期误判「官方没有 i686 gnullvm」，走过一次弯路，已切回 gnullvm。）

### 32 位 TIP 注册表要写两遍

`HKLM\SOFTWARE\Microsoft\CTF\TIP` 是**被 WOW64 重定向**的（CTF 下只有 `SystemShared` 是共享键），
32 位进程读的是 `HKLM\SOFTWARE\Wow6432Node\Microsoft\CTF\TIP`。
只写 64 位那份的话，32 位宿主里飞鹤根本不出现在输入法列表。
`installer\install_tip.ps1` 用同一个函数把 CLSID + Category + LanguageProfile 写进两个视图。

## 安装 / 卸载

安装包是**用户级**的（`RequestExecutionLevel user`），默认装到 `%LOCALAPPDATA%\Feihe`：

```powershell
powershell -ExecutionPolicy Bypass -File installer\build_setup.ps1
# 产物：dist\Feihe-Setup-0.3.0.exe
```

不弹 UAC 的原因不只是「省一步」：输入法的 DLL 跑在记事本 / Word / 浏览器这些普通权限
进程里，它们写不了 `Program Files`。而 0.3.0 起配置和词频都存在安装目录，装到
`Program Files` 的话写入会被 UAC 重定向到 `VirtualStore`（32 位宿主）或直接失败
（64 位宿主），「压缩目录即备份」就变成假象。注册表也全部走 HKCU（COM CLSID + CTF TIP），
卸载同样不需要提权。

开发期也可以直接用脚本（同样不需要管理员）：

```cmd
cd installer
register.cmd      :: 初始化个人词库 + 注册 COM/TIP + 加入当前用户键盘列表
unregister.cmd    :: 全部移除
```

安装后到 `设置 → 时间和语言 → 语言和区域 → 中文(简体) → 语言选项 → 键盘` 里应出现「飞鹤拼音」，
用 `Win+Space` 或 `Ctrl+Shift` 切换。**若列表未刷新，注销重登一次**（输入法列表由 shell 缓存）。

**从 0.2.x 升级**：旧版装在 `C:\Program Files\Feihe` 且注册在 HKLM。新版装到
`%LOCALAPPDATA%\Feihe`、注册在 HKCU（优先级高于 HKLM），所以装完直接生效；
`config.ini` / `freq.txt` / `phrases.txt` / `pinned.txt` 会在首次启动时从
`%APPDATA%\Feihe` **自动复制**过来（复制不删原件）。旧目录可以在「程序和功能」里卸掉。

注册链路上踩过的坑（DLL 部署到稳定路径、User Profile 不是 `SortOrder`、`input.dll` 没有
`UninstallLayoutOrTip`、隐藏的 `Enable = 0`）都记在 `handoff.md`「关键事实」里。

## 打安装包（NSIS）

开发期用 `register.cmd` 就够；要发给别人则用安装包，一键装到 `%LOCALAPPDATA%\Feihe`（用户级，不需要 UAC）：

```powershell
powershell -ExecutionPolicy Bypass -File installer\build_setup.ps1
# 产物：dist\Feihe-Setup-0.3.0.exe
```

`build_setup.ps1` 做四件事：

1. `build.ps1 -NoUserDict -Arch both` —— **发布模式**重编两份 DLL
2. 校验 `target\build_mode.txt`，确认不是拿带个人词库的构建去打包
3. 编译 `installer\feihe.nsi`（`makensis` 默认找 `D:\soft\nsis`，可用 `-NsisDir` 改）
4. 报告产物路径与体积

只改打包不想重编时加 `-SkipBuild`。

### 为什么发布模式要单独一个开关

`src/user_dict.txt` 是从本机搜狗导出的**个人打字记录（约 5 万条）**，普通构建会并进
`base.bin`。这份东西跟着 DLL 发出去就抠不回来了。所以 `build.rs` 认环境变量
`FEIHE_NO_USER_DICT=1` 时跳过它：

| 构建方式 | base.bin | 64 位 DLL |
| --- | --- | --- |
| 普通 | 86749 条 / 6.5 MB | 7.0 MB |
| `-NoUserDict`（发布） | 46492 条 / 2.9 MB | 3.6 MB |

`build_setup.ps1` 还会读 `src\user_dict.txt` 的条数做二次兜底 —— 万一有人用普通构建的
产物打包，它直接报错退出；确实想带个人词库得显式加 `-AllowPersonalDict`。

### 安装包里为什么没有 Python

`tools\*.py`（`import_sogou.py`、`gen_assist.py`、`gen_dict.py`、`smoke_com.py`）全是**开发期**工具：
导词库、生成辅助码、跑冒烟测试。运行时一个都不需要，所以不随安装包分发，
也就没有内置 Python 的必要。安装包实际只装 4 个文件：

```
feihe.dll          64 位
feihe32.dll        32 位
install_tip.ps1    注册脚本（卸载要用，出问题也能手工重跑）
uninstall_tip.ps1  注销脚本
```

`register.cmd` / `unregister.cmd` 是开发期的等价物，不进安装包。

### 打包踩过的坑

完整清单在 `handoff.md`「安装包（NSIS）」，这里只留最容易重复踩的三条：

- **`.nsi` 和每个 `.ps1` 都必须带 UTF-8 BOM**。NSIS 只在有 BOM 时按 UTF-8 解析 `.nsi`；
  PowerShell 5.1 读无 BOM 的 `.ps1` 用系统 ANSI 代码页（简中 = cp936），UTF-8 中文按 GBK
  解码会吞掉字符串的闭合引号，整个脚本解析失败。两边的报错都完全指不到真因。
- **DLL 必须用 `File` 内嵌**，不能 `CopyFiles`。后者是**运行时**拷贝，源路径写的是构建机上的
  `target\...`，用户机器上根本没有，打出来的包只有 192 KB 空壳。现在是先 `File` 解到
  `$PLUGINSDIR\ime`，再从那儿 `CopyFiles` 到 `$INSTDIR`。
- **覆盖被占用的 DLL 只能「改名再拷」**。ctfmon / explorer 已经把旧 DLL 映射进进程，
  直接覆盖会失败；Windows 允许**重命名**已映射的文件。改名之后还得重启 ctfmon 才生效
  ——`install_tip.ps1` 末尾杀一次，系统会按需自动拉起。**只杀不拉**：从提权进程手动启动
  ctfmon 会拿到高完整性令牌，UIPI 挡掉它和普通应用之间的窗口消息，输入法直接瘫痪。

安装包**未签名**，首次运行会撞 SmartScreen「已保护你的电脑」提示，点「更多信息 → 仍要运行」。

  [pinyin-data](https://github.com/mozillazg/pinyin-data) 取音补进来

最终单字 **8006 个**（去重后），三条覆盖线全绿：

| 字表 | 字数 | 词库覆盖 | 缺 |
|---|---|---|---|
| 《通用规范汉字表》 | 8105 | 7896 可编码的全部 | 0 |
| GB2312（一级 3755 + 二级 3008） | 6763 | 6763 | **0** |
| 合计去重 | — | **8006** | — |

```bash
python tools/gen_dict.py               # 下载（缓存 _ice*.yaml）并生成
python tools/gen_dict.py --no-download # 只用缓存
```

输出格式是 `词<TAB>全拼`（音节空格分隔），按词频降序。**不存双拼码**——存码等于把方案
焊死在数据里，切小鹤/微软就得重新生成整个词库，导入导出也只能同方案流通。

> **单字为什么全收而不按词频截断？**
> 早期这里取词频前 3500 个单字，结果某个生僻姓在 8105 字表里排 5402 名
> （词频 796，而第 3500 名的下限是 11418）——被直接截掉，翻页也翻不到，表现成
> 「这个字根本打不出来」。生僻字在候选列表里只是尾部多一行，缺了却是硬伤，
> 姓名、地名、古籍用字都吃这个亏。现在 8006 个可编码单字全收，回归测试
> `rare_name_chars_are_reachable` 钉死。

> **为什么还要补 GB2312？**
> 《通用规范汉字表》并不包含全部 GB2312 二级字——实测 GB2312 的 6763 个汉字里有
> **110 个**不在 8105 表里：`嬲 欷 榘 憝 揎 摺`，以及 `忄 亻 扌 丌 丬 丶 丿` 这类
> 部首部件。用户输入「亻」或者打「摺」的时候同样是「这个字不存在」的体感，
> 所以按 GB2312 做兜底补字，拼音从 `pinyin-data` 取，**词频记 0**（排序时落在
> 每个码的最后，不影响常用字的位置）。
>
> **GB2312 是下限，不是上限。** GBK 里那两万多个字（大量异形字、繁体字、日韩
> 汉字）没有收：需要繁体时用「字形 = 繁体」由 `zhconv` 实时转，不需要在词库里
> 再存一份繁体字表；异体字属于「知道全拼也未必知道该用哪个」的范畴，收了反而
> 让候选变长。

### 多音字：一个词条可以有多个读音

`dict.txt` 里同一个字可能出现多行（`弹<TAB>dan`、`弹<TAB>tan`），这些是**独立条目**——
各自编出不同的双拼码，落在不同的前缀区间里。构建期去重的键是「词 + 拼音」，不是「词」。

> 早期按词去重（先出现的赢），后果是**多音字只剩第一个读音**：打 `tj`（tán）查不到
> 「弹」，于是「弹窗」根本造不出来——只能翻页找一个形近字。同理 `的 de/di`、`行 xing/hang`、
> `重 zhong/chong` 全都缺一边。597 个多音字吃过这个亏。
> 回归测试在 `dictenc::tests::polyphone_keeps_every_reading`。

同一个词的两个读音不会同时出现在一个候选列表里（码不同），即使出现，
`dict::collect` 还有一层按词去重兜着。

### 补充表：`src/extra_dict.txt`

rime-ice 是「书面语料」词表，缺一批日常真的会打的词：电脑操作（输入框、下拉框、
任务管理器）、网络生活（短视频、评论区、优惠券）、办公（周报、纪要、排期）。
这些词放在 `src/extra_dict.txt`，构建时并进 `base.bin`，**优先级低于 `dict.txt`**——
只补确实缺的，不会覆盖已有的高频词。

加了就有人受益，删了用户就得自己造。改这个文件时先跑一遍去重检查（`build.rs` 会按
「词 + 拼音」跳过重复），确认真的缺再往里加。

一条新词要过四道关才进得去：词库（`dict.txt` + `extra_dict.txt`）里没有、只含汉字、
长度在分类范围内、拼音能编出双拼码。拼音用 pypinyin 的词级判断（`银行`→`yin hang`），
生僻字和地名古音它也会错，所以 `tools/pinyin_overrides.txt` 钉了 60 多条人工校正，
`tools/gen_extra.py` 还会把「pypinyin 读音不在词库登记读音里」的词全部列出来复核。

**这条不能只靠人眼。** `dict::tests::generated_words_are_all_searchable` 把 12 份文件
全量跑一遍：按文件里的拼音编码、按码查回来，必须命中它自己。拼音错一个（这个词
就等于不存在）测试立刻红。

改词流程：改 `tools/wordlists/<分类>.txt` → `python tools/gen_extra.py --write` →
`cargo test --lib generated_words`。**不要手改 `src/extra_*.txt`**，下次生成会覆盖。

拼音要从 `词<TAB>全拼` 两列对得上，所以词表里只写词、不写拼音（除了 overrides）。

真正的双拼码在**构建期**由 `build.rs` 算好：9.1 万条 × 三套码（小鹤/微软/全拼去空格），
各生成一张按码升序的下标表，连同偏移表和字节池写成一个扁平文件 `base.bin`，用
`include_bytes!` 嵌进 DLL。运行时只是「读两个 u32 数组 + 二分」，**零解析**。

这么做有两个直接好处：`Activate` 里原本 81ms 的编码开销归零；数据落在 DLL 的 `.rdata`
段，由 PE 加载器 mmap，**多个进程共享同一份物理页**，不再是每个进程各背 9.2MB 私有堆。

> 注意：不要换成 `luna_pinyin.dict.yaml`。它第三列是「多音字概率」不是词频
> （`丁 ding 99.93%`），按它排序会把生僻字排到最前面。

### 用户词库：txt 是源，bin 是产物

装完之后还能往里加自己的词，两种形态并存：

| 文件 | 角色 |
| --- | --- |
| `<安装目录>\user_dict.txt` | **源文件**（运行时拷到数据目录），人可读、可手改、可导出（`词<TAB>全拼`） |
| `<安装目录>\user.bin` | 上面那份**编译出来的 FHDB 二进制**，运行时 mmap |

设置窗里三个按钮：`导入词库…` / `导出词库…` / `编译个人词库`。**导入后会自动编译**，
所以正常情况下你不用管 `user.bin`。

「编译个人词库」编译的是**你的** `user_dict.txt`，不是程序本身。从没导入过个人词库时
那个文件不存在——这时点按钮不报错，只提示「还没有个人词库」，因为它本来就无事可做
（早期版本会甩一句 `读不到 user_dict.txt：系统找不到指定的文件`，看着像崩了）。

为什么值得编译：

| | 文本覆盖层（旧） | `user.bin` mmap（现在） |
| --- | --- | --- |
| 5 万条首次可用 | 每进程 124.6 ms | 每进程 **0.75 ms** |
| 内存 | 每进程 ~6 MB 私有堆 | 共享页缓存，全系统一份 |
| 查询 | 堆上二分 | 和 `base.bin` 完全同一条零解析路径 |
| 一次性成本 | 无 | 编译 139.9 ms（点按钮时付） |

判定规则是「产物不能比源旧」：如果 `user_dict.txt` 的 mtime 比 `user.bin` 新
（说明你手改了 txt 但没重新编译），运行时自动退回文本覆盖层，避免「改了不生效」。
点一次「编译个人词库」就回到快路径。

`user.bin` 和 `base.bin` 用的是**同一个编码器**（`src/dictenc.rs`，`build.rs` 与运行期
各以 `#[path]` 引入一次）。两边各写一份的话，改了布局忘改另一边，症状是「导入的词
静默不生效」，极难查。

> 跨进程生效时机：别的程序还映射着旧 `user.bin`。每个程序下次切换输入法
> （`Activate`）时会重新探测文件 mtime 并重映射，不用重启。

## 导入本机搜狗拼音的词库

飞鹤支持把你的搜狗个人词库搬过来——**打过什么词，飞鹤里就有什么词**。

```bash
python tools/import_sogou.py              # 自动发现并全量重建 src/user_dict.txt
python tools/import_sogou.py --list       # 只列出发现了哪些词库文件，不写
python tools/import_sogou.py --dry-run    # 只统计不写文件
python tools/import_sogou.py --max-len 8  # 放宽到 8 字短语（默认 6）
python tools/import_sogou.py --dir "D:\soft\sogoupinyin\用户数据\SogouPY.users\00000001"
```

**可反复执行**：每次都从搜狗原始文件全量重建，不累积、不残留。搜狗用久了想刷新，
直接再跑一次，然后 `build.ps1` + 替换 DLL 即可。

### 它读哪些文件

自动从注册表 `HKLM\SOFTWARE\WOW6432Node\SogouInput` 找安装目录，然后扫：

| 文件 | 内容 | 提取方式 |
|---|---|---|
| `用户数据/SogouPY.users/<id>/sgim_gd_usrbg.bin` | 背景词库（打字历史，主力） | 严格校验 |
| `用户数据/SogouPY.users/<id>/sgim_gd_usr.bin` | 用户词库 | 宽松提取 + 注音过滤 |
| `Scd/*.scel` | 细胞词库（要自己下载放进去） | 头部自适应解析 |
| `用户数据/SogouPY.users/<id>/*dict*.txt` | 手动导出的文本词库 | 按行取首列 |

### 格式怎么破的

搜狗没有公开文档，但实测词条是**明文 UTF-16LE**，只是外面套了私有二进制头。
`sgim_gd_usrbg.bin` 的记录尾部有个「字节长 + 6」字段，正好当校验和用，能把字节错位
产生的假词（`吐嚕`）全滤掉；`sgim_gd_usr.bin` 没这个字段，退回宽松规则 + 注音过滤。
细节见 `handoff.md`「关键事实」里的搜狗三行。

### 注音策略（多音字为什么是准的）

1. 先在基础词库 `src/dict.txt` 里查——那里已经是「词 → 小鹤双拼码」，
   多音字天然正确（`重复`→`csfu`、`重要`→`zsyc`、`角色`→`jtse`）
2. 查不到才逐字注音：单字取 8105 字典里词频最高的读音，再用小鹤表编码

实测 5.2 万条里 3772 条命中基础词库、4.8 万条走逐字注音。逐字注音对多音字短语
（`重要`/`重复`）可能选错读音，这类词打不出候选是正常现象——按 `--max-len` 收窄
或手动改 `user_dict.txt` 都行。

### 两个词库怎么合并

分两个阶段，**不是运行时合并**：

1. **构建期**：开发机的 `src/user_dict.txt`（如果有）和 `src/dict.txt` 一起喂给
   `build.rs`，按词面去重、按码稳定排序，编成 `base.bin` 嵌进 DLL。
   发布构建（`FEIHE_NO_USER_DICT=1`）跳过前者——个人打字记录不能随包发出去。
2. **运行期**：`<安装目录>\user.bin`（由 `user_dict.txt` 编译而来）单独 mmap，
   查询时**先查用户词库、再查 `base.bin`**，用户词天然排在前面，不需要合并两张表。

两阶段都走 `dictbin` 的同一套零解析二分。查询成本是两次前缀区间定位，
和词库大小基本无关——`base.bin` 4.7 万条也好、8.7 万条也好，都是「读两个 u32 数组 + 二分」。

> 早期版本是运行时把两份文本解析进堆、合并、稳定排序，5 万条要 125 ms/进程、
> 每进程多背 6 MB 私有堆。换成「构建期预编码 + 运行期 mmap」之后降到 0.75 ms 且全系统共享一份页。

## 已知缺口

写在这里是为了让人一眼看到边界，而不是试了才发现。每一条都对照代码核实过。

**没做的功能**

| 项 | 说明 |

| 外挂式输入 | 既不接 UILess、也不显示组合串的程序里打不了字；键盘钩子 + 注入进程会被反作弊判成外挂，不做 |
