# 我受够了 134 MB 的搜狗，于是用 Rust 写了个 2.54 MB 的开源输入法

> 一个只有几 MB、不联网、不弹窗、无账号、源码全开的双拼输入法，Windows 和 Android 共用同一份引擎。

先说结论：**飞鹤输入法（feihe）**，Windows 端安装包 **2.54 MB**，装完约 **12.6 MB**，单字 8573、词条 74869，不联网、不弹窗、无账号、密码框一个字都不接管。原生小鹤双拼，一简 26 键 + 二简 370 词，402 项 Rust 单测 + 94 项 Android JVM 单测全绿。开源，Rust 全量源码，改一行 30 秒出包。

不是「只服务小众」的玩具——**目标是真把搜狗替下来**。

---

## 一、为什么又造一个输入法

事情起因很朴素：我打开任务管理器，发现一个输入法占了 134 MB 硬盘、81 个文件，用户数据另占 7.8 MB，还常驻两三个进程，导入表里一堆 `wininet` / `winhttp` / `ws2_32`。

我不需要它联网。我不需要它弹热点。我不需要一个输入法登录账号、云同步我的打字记录。

那我能不能要一个「只会打字」的输入法？

市面上的答案要么是「功能多但重」，要么是「轻但词库荒」。我想要的其实很具体：

- 小鹤双拼是**一等公民**，不是全拼输入法附带的双拼模式；
- 词库够日常，词频本地学习，但**绝不联网**；
- 体积小到可以忽略，启动快、能看懂代码；
- 桌面和手机**同一套逻辑**，不要这边打出来是「张三」，那边是「张叁」。

于是就有了飞鹤：一份 Rust 引擎 `feihe-core`，两个壳——Windows TSF（`windows-rs` / COM）+ Android IME（Kotlin / JNI）。

> 「桌面改了什么，手机就是什么。」候选顺序、词频、联想、分段，两端天然一致，不存在对不上的问题。

## 二、先摆数据：它到底有多小

体积是本机实测（搜狗 16.3.0.3446，装完 134 MB / 81 个文件，用户数据另占 7.8 MB）：

| 维度 | 飞鹤 | 搜狗拼音 | 微软拼音 |
|---|---|---|---|
| 安装包 | **2.54 MB** | 百 MB 量级 | 随系统预装 |
| 装完占用 | **约 12.6 MB** | 134 MB + 用户数据 | 随系统 |
| 广告 / 热点推送 | **没有这功能** | 有（可关） | 无 |
| 账号 / 联网 | **完全不需要** | 登录后云同步 | 账户可选 |
| 开源 | **是（Rust 全文可改）** | 否 | 否 |
| 小鹤双拼 | **原生，不用装方案** | 支持 | 支持 |
| 一简 / 二简 | **原生（26 键 + 370 词）** | 随方案 | 无 |
| 词库规模 | 7.5 万条 | 数百万级云词库 | 系统词库 |
| 生僻字 | **GB2312 + 规范汉字表全收，缺 0** | 全 | 全 |
| 动态词频 | 本地学习 | 云端 + 本地 | 本地 |
| 简繁切换 | Windows NLS，零体积 | 有 | 有 |
| 模糊音 | 原生 9 条（默认关） | 有 | 有 |
| 拼写纠错 | 零候选时一键猜回来 | 有 | 有 |
| 语音输入 | Android 离线有 | 有 | 有 |
| 云同步 | **无** | 有 | 有 |
| 平台 | **Windows + Android，共用引擎** | 多平台 | Windows |

**它真正占优的地方，几乎都是「少」带来的：**

- **体积差两个数量级。** 词库在构建期预编码成扁平二进制，`include_bytes!` 嵌进 DLL 的 `.rdata`，PE 加载器 mmap 它——多个进程（记事本、Word、浏览器）**共享同一份物理页**。没有运行时解析、没有每进程私有堆，7.5 万条词库也只值 4.8 MB。
- **没有联网代码。** 这不是「隐私承诺」，是「没写这个功能」。实测 18 个导入 DLL 全是 `kernel32` / `user32` / `ole32` / CRT 这一层，没有 `wininet` / `winhttp` / `ws2_32` / `urlmon`。你自己就能验：

  ```cmd
  objdump -p feihe.dll | findstr /i "DLL Name"
  objdump -p feihe.dll | findstr /i "internet winhttp ws2_32 urlmon"
  ```

- **不自动上屏。** 长句一定是「你按空格才落字」，绝不替你猜一半先写进文档。自动组出来的词不对，退格能把它拆回单个字。
- **候选不设上限。** 这个码下有多少条就出多少条，按 `+` 能一直翻到最后一个。宁可多翻几页，也不能让想打的字根本不在列表里——`ji` 有 128 个单字，砍到 45 条时「玑」就永远出不来。

## 三、双拼是一等公民

每个音节固定两键：声母键 + 韵母键。

```text
声母键位
zh=v   ch=i   sh=u
其余声母直接用字母本身（b p m f d t n l g k h j q x r z c s y w）

韵母键位（口诀：秋闱软月云梳翅，松拥黛粉更航安，
          快莺两望奏夏蛙，撇草追鱼滨鸟眠）
q=iu  w=ei  e=e   r=uan t=ue  y=un  u=u   i=i   o=o/uo p=ie
a=a   s=ong d=ai  f=en  g=eng h=ang j=an  k=uai l=iang
z=ou  x=ia  c=ao  v=ui  b=in  n=iao m=ian
```

零声母是最容易记错的一条，按韵母长度分三种：

| 韵母长度 | 规则 | 例 |
|---|---|---|
| 1（a o e） | 重复该字母 | 啊 `aa`、哦 `oo`、额 `ee` |
| 2（ai ei ao ou an en er） | 零声母 + 韵母末字母，表现同全拼 | 爱 `ai`、安 `an`、欧 `ou` |
| 3（ang eng） | 零声母 + 韵母所在键 | 昂 `ah`、鞥 `eg` |

所以「按钮」是 `annq`（`an` + `nq`），不是 `ajnq`。这种零声母细节，单元测试直接拿官方反查结果钉死——**双拼的键位表本身就是规格，不是「顺便支持一下」**。

例子：

| 想打 | 全拼 | 实际敲 |
|---|---|---|
| 你好 | ni hao | `nihc` |
| 中国 | zhong guo | `vsgo` |
| 世界 | shi jie | `uijp` |
| 按钮 | an niu | `annq` |
| 爱情 | ai qing | `aiqk` |
| 肮脏 | ang zang | `ahzh` |

**空格**选第一个候选，**回车**把编码原样上屏（`iuliqi` → `iuliqi`），数字键选候选，`←/→` 切逐字选择，`-`/`=` 或 `↑`/`↓` 翻页。

## 四、几个我私心最爱的功能

### 1. 同音字太多时，再加一道「形」——辅助码

`ji` 底下有 128 个单字，想打「记」得翻好几页。辅助码就是音码之后再补一两个字母，用字的「形状」再筛一遍：

```
ji → Tab          （组合串末尾多出一个空格位，等形码）
ji → Tab → m j    → 只剩木字旁，「机」在第一位
```

先连打、再按 Tab 也认：`dd + f + j → Tab`，组合串自动变成 `dd fj`，不用退格重来。

有两种方案可选：

- **自然码辅助码（1 键）**：取部首读音首字母。的 `b`（白）、想 `x`（心）、你 `r`（人）、机 `m`（木）。
- **小鹤音形（2 键）**：首部件 + 末部件，用官方码。计 `yu`（讠+十）、记 `yj`（讠+己）——*这一档正是 2 键胜过 1 键的地方*。

而且**形码打满就出字**：形码和输入完全相等的单字会顶到第一位，不按词频排。`jm → Tab → v o`，第一位就是「简」，哪怕「简单」更常用。

### 2. 翻页时摊开成多行（找生僻字用）

同码字多的码，单行一页只放 9 个。按一次 `=` / `+`（或 `↓`），候选窗会**长高**，一次摊开 5 行 = 45 个：

```
1.机 2.几 3.级 4.及 5.既 6.即 7.集 8.急 9.记
1.计 2.鸡 3.极 4.积 5.挤 6.季 7.寄 8.纪 9.击
1.己 2.济 3.辑 4.击 5.姬 6.讥 7.畸 8.稽 9.迹
```

### 3. 快捷输入：一个 `/` 搞定日期、农历、干支、算式、金额大写

先敲 `/`，后面接命令码，只打首字母也行：

| 输入 | 得到 |
|---|---|
| `/rq` | `2026年11月9日` / `2026-11-09` / `11月9日`… |
| `/nl` | 农历：`农历丙午年九月二十` / `丙午年九月二十` |
| `/gz` | 干支四柱：`丙午年 戊戌月 庚午日 壬午时` |
| `/jq` | 下一个节气：`2026年11月22日 小雪` |
| `/fc` | 反查剪贴板里的汉字写法与编码 |
| `/c1+2` | `3`；`/c123` → 一百二十三 / 壹佰贰拾叁 |
| `/v123` | `壹佰贰拾叁元整`（开票专用，大写在前） |
| `/u4e00` | `一`；`/uuid` → 随机 v4 UUID |

只敲一个 `/` 会列出全部命令的预览，不用记码。**Android 端同样支持**——命令表放在 `feihe-core` 的 `quick` 模块里，两端共用同一份源码。

### 4. 不联网的联想

打完「北京」摆出「大学 / 时间 / 地区」，数字键或鼠标点就上屏。两张表：内置 2 万条（词库复合词反推，装完就有）+ 你自己打出来的词对（永远优先）。单字、三字、更长的词都能接，长词查不到就取最长的已知后缀。**不联网、不加载语言模型**，安装包只涨一百来 KB。

### 5. 易错词读音标注 + 错音容错

候选里直接带调（「重庆」显示 `chóng qìng`），哪怕你打成 `zhongqing` 也能打出来。753 个易错词，按错读音也照样出。

## 五、手机上也是同一个引擎

Android 版是标准 `InputMethodService`（Kotlin 壳 + JNI），引擎就是上面那份 `feihe-core` 编成的 `libfeihe_android.so`。候选、词频、联想、分段**两端不会各说一套**。

已实现：26 键 QWERTY、双拼 / 全拼双模（查不到自动退回全拼）、逐段选择（点候选条里的分段改某一截）、数字选词行、长按 ⇧ 上档锁定、**离线语音**（按住 🎤 说话，silero VAD 裁静音、paraformer 识别、句末补标点）、验证码提示、剪贴板历史、数据备份（导出 / 导入 zip）、设置页。

全程不联网，录音不落盘、不上传。

> 目前单测与打包全绿，**真机手感仍待验**（adb 掉线）——不藏着，写在明面上。

## 六、还没做的，也写在明面上

省得你试了半天才发现。每一条都对着代码核实过：

| 还差的能力 | 现状 |
|---|---|
| 云同步 / 云词库 | 没有，词频只在本机（这是「不联网」的代价，不打算补） |
| 词库规模 | 7.5 万条 vs 数百万级云词库；生僻术语、新词、人名地名靠用户词库补（**支持导入搜狗个人词库**） |
| 皮肤商店 | Windows 3 套内置、Android 1 套，没有在线皮肤 |
| 手写输入 | 两端都没有 |
| 候选窗多行展开 | Windows 有；Android 是单行横向滚动 |
| 组合串下划线 | `ITfDisplayAttributeProvider` 未实现（Windows） |
| 安装包签名 | 未签名，首次运行会撞 SmartScreen |

目标是替换搜狗，但**不靠「功能比搜狗多」取胜**：靠的是同样的日常能力、零广告零联网、体积小两个数量级、源码全开可改，以及桌面 / 手机共用一份引擎带来的行为一致。上面这张表就是差距清单，也是后续排期的依据。

## 七、怎么跑起来（Windows）

需要 Rust、llvm-mingw（解压到 `C:\llvm-mingw`）、以及 gnullvm target。**不需要 MSVC，也不需要 CMake。**

```powershell
# 1. 准备 target
rustup target add x86_64-pc-windows-gnullvm
rustup target add i686-pc-windows-gnullvm

# 2. 一键构建：64 + 32 位两份 DLL，自动校验 PE 头并跑加载冒烟测试
powershell -ExecutionPolicy Bypass -File build.ps1

# 3. 打安装包（发布模式，排除本机个人词库）
powershell -ExecutionPolicy Bypass -File installer\build_setup.ps1
# → dist\Feihe-Setup-0.3.18.exe
```

装好后到「设置 → 时间和语言 → 语言和区域 → 中文 → 语言选项 → 键盘」里就会出现「飞鹤拼音」（列表由 shell 缓存，没刷新就注销重登一次）。

**为什么两份 DLL？** in-proc COM 的位数必须和宿主进程一致：64 位宿主加载 `feihe.dll`，32 位 Office 之类加载 `feihe32.dll`，同一个 CLSID 背后挂两个文件。

数据全部和 DLL 放在安装目录（默认 `%LOCALAPPDATA%\Feihe`）里：`config.ini`、`freq.txt`、`phrases.txt`、`pinned.txt`、`demoted.txt`、`custom.txt`、`next.txt`。**压缩一份安装目录就是完整备份**，换机、重装直接拷回去。

## 八、写在最后

飞鹤不是一个「什么都做」的输入法，它是一个**减法做到极致**的输入法：不联网、不弹窗、不登录、不猜你的句子、不堆功能。省掉的东西，最后都变成了体积、启动速度和可读的代码。

如果你也是小鹤双拼用户，也受够了臃肿和打扰，欢迎试试、欢迎提 issue、欢迎直接改源码——**不喜欢候选顺序、想加快捷输入命令、想换皮肤颜色，改 Rust 源码，30 秒出包，不用等官方发版。**

这正是开源输入法最爽的地方：它听你的，而不是听运营的。
